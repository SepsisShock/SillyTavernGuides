Prompt Post-Processing

Think of sending packages. SillyTavern first gathers the material for a request and places it into messages, like items packed into shipping boxes. Each box has a label such as System, User, or Assistant. Prompt Post-Processing (PPP) decides how those boxes are combined or relabeled before the request is sent to the AI API.

1. The journey of a request

SillyTavern collects prompt material
Main Prompt, character information, scenario, lore, examples, Author's Note, chat history, Post-History Instructions and enabled injections
↓
Prompt Post-Processing
Combines or relabels message boxes to suit the selected setting
↓
AI API receives the processed request
The model uses it to produce a reply

These items do not always appear in the same order. Their position, role and inclusion depend on prompt configuration, triggers and context limits.

3. The labels on the boxes

The label tells the API what kind of message it is. Two boxes can contain similar text but have different roles. PPP can change the packaging or a role label without rewriting the text inside.

4. Why does PPP only apply to Chat Completion?

Chat Completion and Text Completion send prompts differently. That is why the PPP settings in this guide apply to Chat Completion.

Chat Completion

Separate messages with role labels

SYSTEMMain Prompt
USERHello!
ASSISTANTHi there!

PPP can combine message boxes or change their role labels.

Text Completion

One continuous text prompt

ONE TEXT DOCUMENT
System: Instructions...
User: Hello!
Assistant: Hi there!

Context and Instruct Templates help format the text instead.

In Chat Completion, roles are separate message labels that PPP can work with. In Text Completion, words like “User:” and “Assistant:” are part of the text itself, not separate API message labels.

5. Try each PPP setting

Click a setting to see the same request repackaged. The cardboard packages represent messages; the colored shipping labels show their roles. This example includes a character’s First Message / Greeting. The contents are illustrative, not a literal API request.

Real output depends on the prompt order and API-specific behavior. This illustration demonstrates grouping, not exact backend transformations.

SettingWhat happens to the boxes?
NoneLeave the labeled boxes as they are, except for any changes the API requires.
Merge consecutiveCombine neighboring boxes that have the same role label.
Semi-strictKeep at most one initial System box. Repackage later System messages as User messages and combine neighboring boxes with matching roles.
StrictLike Semi-strict, but make sure a User message comes before the first Assistant message, adding a placeholder User message if needed.
Single user messagePack the prompt into one large box labeled User.

6. What about tool calls?

A tool call is when the AI asks a tool to do something, such as searching the web, then receives a result. The “with tools” variants of Merge, Semi-strict and Strict are designed to preserve tool-call information.

PPP choiceTool-call handling
NonePPP does not explicitly strip tool calls
Merge / Semi-strict / Strict, without toolsTool-call information is removed
Merge / Semi-strict / Strict, with toolsTool-call information is preserved
Single user messageNot a tool-preserving variant

“With tools” does not grant a model tool-calling abilities. The model, API and SillyTavern setup must support tools too.

7. Why do these options exist?

Different APIs accept different message formats. Some want just one System message. Others need the conversation to start with User. PPP helps package the already-assembled messages in a format the API can accept. Think of different delivery destinations having different rules for box labels and grouping.

Example: Strict requires User first
Assistant: Hello!
User: Hi!

↓ If necessary, Strict can add a placeholder User message first (added by Strict, not typed by the user):

User: [Start a new chat] (Added by Strict)
Assistant: Hello!
User: Hi!

9. How can I see what was actually sent?

Use SillyTavern's Prompt Itemization on an AI reply, or inspect a suitable prompt inspector or request log. This is more reliable than guessing what a setting did.

Remember: SillyTavern assembles the prompt material first. PPP changes how the resulting message boxes are packaged or labeled before the AI API receives them. It does not decide which character details, lore, or history are selected.
